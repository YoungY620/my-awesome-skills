# 课程材料 / 论文 → 在线教材

把源材料转成**信息密度高的教材散文**：保留全部知识点，删过渡语/语气词/重复；章节结构与原材料一致；内容只许来自材料本身。默认双语（英文默认 + 中文 /zh/），用 mdBook + GitHub Pages 发布。多本书可以共用一个站点。

## 环境准备（一次性）

- `poppler`（pdftotext/pdftoppm）、`ffmpeg`、`yt-dlp`、`mdbook`（cargo 安装）、`gh` CLI（repo + workflow 权限）。装完真的跑一下：`Bad CPU type` 说明是错误架构的二进制。
- 无头浏览器（Playwright 之类），用于真实渲染检查——这是必备工具，不是可选。
- OCW 课程视频可从 archive.org 下低码率版，够看清画面即可。
- mdBook 版本敏感：0.5 与 0.4 的 DOM id 不同（见"常见坑"），动手前先 `mdbook --version`。

## 流程

### 1. 材料整理
- **映射关系优先**：从课程元数据解析「视频 ↔ 讲次 ↔ 课件 ↔ 作业 ↔ readings」的对应，按讲次归档。
- 课件 `pdftotext`；字幕去时间轴/去重成纯文本。课件文本极短说明内容在图里，必须读图提取。
- **每讲的 readings 也是课程材料，必须获取**：教材章节、论文、讲义，优先开放获取（arXiv、PMLR/NeurIPS proceedings、作者主页预印本、免费教材站、机构库/NSF PAR 等官方仓储）。大部头教材只提取指派章节。付费墙先找作者预印本，找不到记录"未能获取"并继续——绝不用盗版站。

### 2. 章节撰写（每讲一个子代理，并行）
- 输入：课件文本 + 转录 + 课件 PDF + 该讲 readings 提取文本。
- 按原讲座顺序组织；定义/数字/公式/定理/算法/示例逐条保留；不得引入课程外内容。
- **readings 合并**：课件只给结论而 readings 给出完整定义、证明、精确复杂度界时，无缝并入对应小节；超出本讲主题的不并入；以增为主，篇幅增长控制在约 1.5 倍内。
- 插图：渲染课件页 → 图像理解选图 → 精确裁掉标题栏/页脚 → 每张裁完回看验证。纯文字表格重排为 Markdown，不截图。
- 数学用 MathJax。每章末尾加要点小结。

### 3. 视频增量核验（有视频时，每讲一个子代理）
找出「视频画面有、课件+转录都没有」的知识：全局接触表扫描全片（标出板书段/演示段/外部片段/与课件不同的页），再按字幕视觉线索关键点抽帧核对。增量内容补入章节；版权画面（赛事转播等）不截图，只文字转述。

### 4. 双语构建
- 英文在站点根，中文在 `/zh/`；两个 book root，文件名一致，assets 各一份。
- 第二语言以该语言的源材料为权威，第一语言章节只作结构参照——撰写过程就是第二次交叉核对，发现的错误两边同步修正。
- 顶栏语言切换按钮同页互跳。**路径计算必须基于 mdBook 的 `path_to_root`（页面相对 book root 的深度）反推 book root，再拼 `/zh/`**；不要用"在最后一段前插 `/zh/`"这类写法，多级目录下必然算错。
- **术语表（推荐）**：维护一份术语 YAML（术语、对照写法、一句话简介、详解、首见章节），构建期生成附录页（中文按拼音分组、英文按字母分组），运行时用 additional-js 把正文术语包成 Wikipedia 式悬浮卡（hover/点按显示简介，点击跳附录）。链接化必须等 MathJax 排版完成后再执行并跳过公式/代码/标题，同一文本节点内要持续向后链接（否则排在常见术语后面的词永远得不到链接），每个术语每页限量加链防刷屏。**加链预算要初始化成"每术语上限"**，否则一个都链不上；每术语的 fragment 由不同子代理并行撰写、主代理合并去重（按归一化后的术语名去重，否则 `Data origin authentication` 与 `data-origin authentication` 会撞 id）。

### 5. 部署
GitHub Actions 构建并发布 Pages（英文根 + 中文 /zh/ 子目录），`gh` 建库并开启 workflow 模式 Pages。push 即自动重新部署。
**首次必须在 CI 之外手动开 Pages**：`gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow`。`actions/configure-pages@v5` 的 `enablement: true` 用默认 workflow token 创建站点会报 `Resource not accessible by integration`。

**署名要求**：生成的教材首页（README/课程简介页，中英文两个版本）必须注明由本 skill 生成，并附**可点击的链接**（mdBook 不会把裸 URL 自动变成链接，必须写成 `<URL>` 或 `[文字](URL)`，生成后要在渲染页面上确认它真的是 `<a>`）：
`本书由 course-textbook-builder 流程生成（<https://github.com/YoungY620/my-awesome-skills>）。`

## 论文精读模式（单篇论文 → 一本书）

材料：论文 PDF（prepub 与正式版都下）、会议讲解视频（若有）、项目主页 / 作者页的 artifacts 与 slides。

- **视频取证**：YouTube 对本机 IP 常返回"Sign in to confirm you're not a bot"，`yt-dlp` 各客户端与 Invidious/Piped 镜像都会失败，浏览器 cookie 文件通常被 macOS 隐私保护拒绝读取。可行的路径是**用内置真实浏览器打开字幕站（如 DownSub），让它的服务器去取官方字幕**，再下载 TXT + SRT。只拿到字幕轨时，要在来源页明确声明"视频未逐帧核验，讲者仅靠画面传达的内容不在教材内"。不要去自动点人机验证。
- 章节按论文自身章节走；攻击/方案标识符（如 `BW01`…、`V1`…`R1`…）原样保留，便于对照 PDF。论文里的表格重排为 Markdown 并**逐格对照页面图像**核对；插图按 300 dpi 裁出并逐张回看。
- 论文与讲解视频不一致时以论文为准，只出现在视频里的内容要标注来源。
- **必须有一章「相关工作与基线」**（Related work and baselines / 相关工作与基线）：把论文重点对标的 baseline，以及 related work 覆盖的整个方向的关键工作，**下载、阅读、整理**成文。做法：
  1. 从论文的 related work、引言、讨论与参考文献里挑出最关键的工作（10–20 篇；SoK/综述类要覆盖它分类下各类别的代表作，取 15–25 篇）。
  2. **只取开放获取版本**：arXiv、IACR ePrint、会议的开放版、机构库、作者主页。按 `年份-作者-主题.pdf` 归档，另存下载 URL。**绝不使用盗版站；付费墙且无作者版就记录"未能获取"并继续，不要用别的东西顶替。**
  3. 逐篇真读（至少摘要 + 威胁模型 + 机制 + 评测），再写。
  4. 按主题组织，不写成 annotated bibliography；逐条分清"**原工作证明了什么**"与"**本文新增了什么**"，引用要用真实读到的数字与结论。
  5. 章末单列 `Sources consulted` / `已查阅的文献`（含链接）与"未能获取"及其原因。
- 难度与耗时按"下载 60 篇左右文献"预估；这一章通常比其他章长，是合理的。

## 多本书共用一个站点（推荐）

- 一个 repo、一个站点，一书一目录：`src/papers/<slug>/`（或 `src/<course-slug>/`），assets 随书放在各自目录下，章节里的相对路径 `assets/xxx.png` 因此仍然成立。
- `SUMMARY.md` 用 `#` 分组 + 两级列表（`- [书名](...)` 下面缩进列各章）；新增一本书只需建目录、加两行。
- 术语表**全站共享**（术语条目可带 `paper`/`course` 字段标明出处，附录页一并展示），运行时通过 `path_to_root` 拼出 `glossary.html` 的正确相对路径。
- 站点首页是全书目录：每本书给摘要 + 链接。
- 这样部署也只部署一次。

## 兜底验证策略（最重要的一节）

**源级检查（构建无警告、链接存在、脚本标签在 HTML 里）永远不等于渲染成功。** 本流程历史上每个重大线上事故——行内公式全站不渲染、公式被 Markdown 解析器吃掉、散文美元被误认为公式定界符、图片裁错、搜索索引语法错误、署名只是纯文本——源级检查全部通过，只有真实渲染才能发现。因此：

1. **每次内容变更后，在本地用真实（无头）浏览器逐页渲染检查**，而不是只在部署后抽查：
   - 等页面 JS（MathJax 等）执行完，再断言：公式确实变成了排版产物、没有残留生 LaTeX/定界符、没有未还原的占位 token、图片全部加载成功、**控制台与 pageerror 无错误**（搜索索引坏掉只能从这里看出来）。
   - 抽查代表页面的截图并实际看一眼（含公式密集页、插图页、首页）。
   - 交互功能在渲染出的页面上实际点一遍：语言切换（在多级目录下点，确认落到对应页而不是 404）、搜索（拉丁查询与中文查询都要试）、术语悬浮卡。
   - 署名等"必须可点击"的链接，直接断言渲染结果里存在 `<a href=...>`，不要只看源码里有没有 URL。
   - **对构建产物做一次内部链接审计**：把每个页面里的本地 `href`/`src` 解析到磁盘上核对。渲染检查只能发现"页面打不开"，发现不了"页面能打开但里面的链接指向不存在的路径"——后者在 mdBook 里是静默的（可能整页被 `404.html` 顶替，且因为相对路径的 CSS 也取不到，用户看到的是没有样式的残页）。
   - 桌面与移动两种视口都跑，检查横向溢出。
2. **本地全绿才允许 push；push 后对线上站点重跑同一套检查**（部署本身也会引入问题，如 CDN 延迟、路径差异）。
3. **插图的正确性只能看图判断**：逐张实际查看，对照源 PDF 原页与正文语境，检查缺漏/多裁/裁错/放错；不能采信撰写者的自述。
4. **交叉核对是免费的质量放大器**：双语撰写、视频核验、readings/文献合并每一轮都会暴露上一轮的错（转录笔误、课件笔误、数字归属错误），发现的错误所有版本同步修正，并在正文注明勘误。
5. 检查中发现的新失败模式，回到流程里从源头修（模板、配置、生成规则），而不是只修单点。

## 常见坑（都是真实踩过的）

- 转录文本不可靠：花色、数字、人名经常错，课件/画面优先；课件本身也有笔误，按数学自洽修正并注明。
- **Markdown 会在 MathJax 之前先解析公式**：反斜杠+标点（`\,`、`\{`）被吞、`}`旁的 `_` 变斜体、`\\` 换行丢失、散文 `\$` 被 Markdown 吃掉反斜杠后又被 MathJax 误认为公式定界符。**只有预处理层能真正解决**：写一个 mdBook 预处理程序，在 Markdown 解析之前把每个公式片段替换成不透明 token（token 里编码原文），构建后再把 token 还原成 `\(...\)` / `\[...\]` 写进 HTML。已验证 mdBook 自带的 `mathjax-support` **不做**这种保护（只注入 MathJax 2），别指望它。
- mdBook 自带的 `mathjax-support` 不处理单 `$` 定界符（加载 MathJax 2 且无配置）——需要自行加载并配置 MathJax（用 `head.hbs` 注入配置 + MathJax 4 CDN，`output.displayOverflow: 'linebreak'` 解决超长公式换行）。
- **搜索索引要单独照顾**：mdBook 的 `searchindex-*.js` 是 `JSON.parse('…')` 的**单引号** JS 字符串，往里面写文本要同时做 JSON 转义**和** JS 单引号转义，否则公式里一个撇号就让整份索引语法错误、搜索全废（页面 `SyntaxError` 才看得出来）。
- **mdBook 不索引中文**：它的分词器只保留 ASCII 词元，索引里没有任何 CJK token，中文查询必然 0 结果。补法是运行时兜底：直接扫描 `window.search.index.documentStore.docs` 的全文做子串检索，复用 mdBook 的结果容器与 `.teaser` 标记；索引是**懒加载**的（首次搜索交互才加载），要轮询等待，必要时用合成 keyup 催一下。注意监听器要挂在 `document` 上做事件委托——mdBook 在初始化时会重挂搜索框，挂在元素上的监听器会失效。
- **SUMMARY.md 里顶层条目与缩进列表之间必须留空行**：`[Glossary](./glossary.md)` 紧跟在嵌套的 `  - [...]` 列表后面时，mdBook 会**静默丢掉这一章**（不报错、不警告，只是没有这一页），于是所有指向它的相对链接全部落空。多本书站点加全站术语表时极易踩到。
- **mdBook 的相对链接按章节文件所在目录解析**：把章节移到子目录（例如从"一书一站"改成"多书一站"）会让所有指向根级页面的链接（术语表、常见问题…）指向不存在的兄弟页。改动目录结构后必须重跑链接审计。
- **mdBook 0.5 给几乎所有 DOM id 加了 `mdbook-` 前缀**（`mdbook-menu-bar`、`mdbook-content`、`mdbook-searchbar`…）。自定义 JS 的 `getElementById` 要兼容新旧两种 id，且必须真实渲染验证按钮/链接确实挂上了。
- LaTeX 的 `` `` `` 引号、非常见宏（`\coloneqq`、`\textsc`）都会在渲染时爆雷；在 MathJax 配置里补 `macros` 是成本最低的修法，靠检查兜底。
- **公式美观也是验收项**：数学与正文的字号/字体协调（行内公式相对中文别太小、`\text{}` 继承正文字体）、展示公式与上下文的间距、长公式在窄屏不能溢出——这些都在真实渲染检查里用桌面+移动两种视口实际看。
- 并行子代理：每个写不同文件天然无冲突（术语表这类共享文件要按章拆成 fragment 再合并）；/tmp 备份与渲染产物要带任务唯一前缀；统一由主代理 commit/push。子代理有并发上限，超了会启动失败，需要事后 resume。
- `.gitignore` 排除 `materials/`、`_site/`、`book/` 等体积大或不该发布的产物；**过程材料（下到的文献 PDF、字幕、渲染产物）放在仓库之外**，只把引用链接写进正文。
- 本地 `python3 -m http.server` 在多页并发检查时会偶发 `ERR_CONNECTION_RESET` / `ERR_SOCKET_NOT_CONNECTED`，表现为随机的"脚本没加载/对象未定义"。单页复检通过即可判定为本地瓶颈，不要误当成站点 bug。
