# 课程材料 → 在线教材

把课程材料转成**信息密度高的教材散文**：保留全部知识点，删过渡语/语气词/重复；章节结构与原课程一致；内容只许来自课程材料本身。默认双语（英文默认 + 中文 /zh/），用 mdBook + GitHub Pages 发布。

## 环境准备（一次性）

- `poppler`（pdftotext/pdftoppm）、`ffmpeg`、`yt-dlp`、`mdbook`（cargo 安装）、`gh` CLI（repo + workflow 权限）。装完真的跑一下：`Bad CPU type` 说明是错误架构的二进制。
- 无头浏览器（Playwright 之类），用于真实渲染检查——这是必备工具，不是可选。
- OCW 课程视频可从 archive.org 下低码率版，够看清画面即可。

## 流程

### 1. 材料整理
- **映射关系优先**：从课程元数据解析「视频 ↔ 讲次 ↔ 课件 ↔ 作业 ↔ readings」的对应，按讲次归档。
- 课件 `pdftotext`；字幕去时间轴/去重成纯文本。课件文本极短说明内容在图里，必须读图提取。
- **每讲的 readings 也是课程材料，必须获取**：教材章节、论文、讲义，优先开放获取（arXiv、PMLR/NeurIPS proceedings、作者主页预印本、免费教材站、机构库/NSF PAR 等官方仓储）。大部头教材只提取指派章节。付费墙先找作者预印本，找不到记录"未能获取"并继续——绝不用盗版站。

### 2. 章节撰写（每讲一个子代理，并行）
- 输入：课件文本 + 转录 + 课件 PDF + 该讲 readings 提取文本。
- 按原讲座顺序组织；定义/数字/公式/定理/算法/示例逐条保留；不得引入课程外内容。
- **readings 合并**：课件只给结论而 readings 给出完整定义、证明、精确复杂度界时，无缝并入对应小节；超出本讲主题的不并入；以增为主，篇幅增长控制在约 1.5 倍内。
- 插图：渲染课件页 → 图像理解选图 → 精确裁掉标题栏/页脚 → 每张裁完回看验证。纯文字表格重排为 Markdown，不截图。
- 数学用 MathJax。每章末尾加要点小结。

### 3. 视频增量核验（有视频时，每讲一个子代理）
找出「视频画面有、课件+转录都没有」的知识：全局接触表扫描全片（标出板书段/演示段/外部片段/与课件不同的页），再按字幕视觉线索关键点抽帧核对。增量内容补入章节；版权画面（赛事转播等）不截图，只文字转述。

### 4. 双语构建
- 英文在站点根，中文在 `/zh/`；两个 book root，文件名一致，assets 各一份。
- 第二语言以该语言的源材料为权威，第一语言章节只作结构参照——撰写过程就是第二次交叉核对，发现的错误两边同步修正。
- 顶栏语言切换按钮按 URL 路径映射同页互跳。
- **术语表（推荐）**：维护一份术语 YAML（术语、对照写法、一句话简介、详解、首见章节），构建期生成附录页（中文按拼音分组、英文按字母分组），运行时用 additional-js 把正文术语包成 Wikipedia 式悬浮卡（hover/点按显示简介，点击跳附录）。链接化必须等 MathJax 排版完成后再执行并跳过公式/代码/标题，同一文本节点内要持续向后链接（否则排在常见术语后面的词永远得不到链接），每个术语每页限量加链防刷屏。

### 5. 部署
GitHub Actions 构建两本并发布 Pages（英文根 + 中文 /zh/ 子目录），`gh` 建库并开启 workflow 模式 Pages。push 即自动重新部署。

**署名要求**：生成的教材首页（README/课程简介页，中英文两个版本）必须注明由本 skill 生成并附链接：
`本书由 course-textbook-builder 流程生成（https://gist.github.com/YoungY620/d4932154735b55903d5a53b5f6f406c9）`。

## 兜底验证策略（最重要的一节）

**源级检查（构建无警告、链接存在、脚本标签在 HTML 里）永远不等于渲染成功。** 本流程历史上每个重大线上事故——行内公式全站不渲染、公式被 Markdown 解析器吃掉、散文美元被误认为公式定界符、图片裁错——源级检查全部通过，只有真实渲染才能发现。因此：

1. **每次内容变更后，在本地用真实（无头）浏览器逐页渲染检查**，而不是只在部署后抽查：
   - 等页面 JS（MathJax 等）执行完，再断言：公式确实变成了排版产物、没有残留生 LaTeX/定界符、图片全部加载成功、控制台无错误。
   - 抽查代表页面的截图并实际看一眼（含公式密集页、插图页、首页）。
   - 交互功能（语言切换、搜索）在渲染出的页面上实际点一遍。
2. **本地全绿才允许 push；push 后对线上站点重跑同一套检查**（部署本身也会引入问题，如 CDN 延迟、路径差异）。
3. **插图的正确性只能看图判断**：逐张实际查看，对照源 PDF 原页与正文语境，检查缺漏/多裁/裁错/放错；不能采信撰写者的自述。
4. **交叉核对是免费的质量放大器**：双语撰写、视频核验、readings 合并每一轮都会暴露上一轮的错（转录笔误、课件笔误、数字归属错误），发现的错误所有版本同步修正，并在正文注明勘误。
5. 检查中发现的新失败模式，回到流程里从源头修（模板、配置、生成规则），而不是只修单点。

## 常见坑（都是真实踩过的）

- 转录文本不可靠：花色、数字、人名经常错，课件/画面优先；课件本身也有笔误，按数学自洽修正并注明。
- **Markdown 会在 MathJax 之前先解析公式**：反斜杠+标点（`\,`、`\{`）被吞、`}`旁的 `_` 变斜体、散文 `\$` 被 Markdown 吃掉反斜杠后又被 MathJax 误认为公式定界符。含数学的站点必须有系统性的公式保护方案，并用真实渲染验证。
- mdBook 自带的 `mathjax-support` 不处理单 `$` 定界符（加载 MathJax 2 且无配置）——需要自行加载并配置 MathJax。
- LaTeX 的 `` `` `` 引号、作业里的非常见宏（`\coloneqq`、`\textsc`）都会在渲染时爆雷，靠检查兜底。
- **公式美观也是验收项**：数学与正文的字号/字体协调（行内公式相对中文别太小、`\text{}` 继承正文字体）、展示公式与上下文的间距、长公式在窄屏不能溢出——这些都在真实渲染检查里用桌面+移动两种视口实际看。MathJax 3 没有自动换行，需要 MathJax 4（`displayOverflow: 'linebreak'`）或手动拆分超长公式。
- 并行子代理：每个写不同文件天然无冲突；/tmp 备份与渲染产物要带任务唯一前缀；统一由主代理 commit/push。
- `.gitignore` 排除 `materials/`（视频体积大）与构建产物。
